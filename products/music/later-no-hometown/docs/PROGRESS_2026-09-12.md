Musical quality of this test was rejected. The test sounded unstable and poorly centered in key.

The important diagnosis was found in the generation log. The input caption requested a minor-key melancholic song, while LM metadata planning produced:

```text
bpm: 81
keyscale: G major
language: unknown
timesignature: 4
```

The resulting DiT prompt later still carried `G major`. This created a conflicting plan relative to the requested mood and showed that automatic LM metadata planning should not be trusted blindly for a tightly controlled reproduction task.

Decision:

```text
For reference reproduction, prefer the source audio to constrain melody, harmony, structure, and timing.
Disable Thinking for the initial Remix/Cover reproduction path.
Explicitly provide metadata when needed instead of allowing the LM to invent conflicting values.
```

## Architecture decision made today

Normal future use should not depend on manual Gradio configuration.

ACE-Step already exposes a localhost REST API. The long-term path is:

```text
Owner request
-> Codex prepares/revises lyrics and style
-> Codex writes a structured job spec
-> Codex starts or verifies the ACE-Step REST API
-> Codex submits the job
-> Codex polls until success/failure
-> Codex downloads/collects WAV candidates
-> Codex performs technical checks
-> Owner reviews the best candidate(s)
-> approval is bound to an exact candidate hash
-> Codex promotes final.wav locally and to Git LFS
-> Codex verifies remote Git/LFS state
-> Codex deletes task-specific intermediates
```

Gradio remains a debugging and manual experimentation surface only.
